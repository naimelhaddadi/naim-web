LH Management

LH Sport & Entertainment Management

Lideré el equipo que diseñó y construyó desde cero la base de datos en SQL Server con la que una agencia deportiva internacional trabaja cada día, y la interfaz web que la alimenta.

  3. 10+ entidades

    • Jugadores

  1. Entender

    El problema no era «hacer una base de datos».

    Era mucha información de jugadores, clubes, ligas, contratos y agentes que no estaba organizada, y el trabajo manual repetitivo que venía con ella.

  2. Diseñar

    Un modelo de cómo funciona de verdad la agencia.

    Más de 10 entidades (jugadores, contratos, traspasos, agentes, clubes, ligas) diseñadas alrededor de las operaciones reales, y cómo se relaciona cada una con las demás. Lideré el equipo que lo construyó.

  3. Construir

    Un sistema relacional, desde cero.

    SQL Server con la lógica de negocio en procedimientos almacenados y triggers de T-SQL, integridad referencial garantizada por el modelo y una interfaz web de captura de datos conectada a la base de datos en tiempo real.

  4. En uso

    La estructura sobre la que trabaja la agencia.

    La agencia la usa cada día, y la interfaz le ahorra al equipo unas dos horas de trabajo manual al día. Salí con una carta de recomendación oficial.

03Proyecto personal

GameStore

Un backend en Java bien estructurado, capa a capa.

Tipo
API REST · Java · Spring Boot
Arquitectura
Controller · Service · Repository · DTO

  1. El objetivo

    No solo endpoints que funcionen: un backend cuya estructura aguante cuando crece.

  2. El enfoque

    Una responsabilidad por capa: el controller habla HTTP, el service guarda las reglas, el repository habla con la base de datos y los DTO dan forma a lo que sale.

  3. El sistema

    Spring Boot con Spring Data JPA, Bean Validation en las entradas y tests unitarios con JUnit 5 y Mockito. Elige un endpoint para seguir una petición a través de las capas.

Tecnología

  • Java
  • Spring Boot
  • Spring Data JPA
  • DTOs
  • Bean Validation
  • JUnit 5
  • Mockito
